# Перенос публичного архива

Локальная утилита забирает публичные страницы `www.cigar-moscow.ru` и создаёт материалы Drupal. Публикация на хостинге и переключение доменов в эту работу не входят. `AGENTS.md` в репозитории нет: правила берутся из README, модели материалов и пилота.

Дампа старой CMS и каталога `content/` на машине нет. Источник — публичные страницы, обойдённые с паузой 0,25 с и сохранённые в `~/.local/share/cigar-moscow/archive`. Этот каталог не входит в Git. Снимок пилота `~/.local/share/cigar-moscow/pilot-2016/` остаётся контрольной выборкой: десять статей пилота в полном снимке побайтово совпадают с ним.

## Приёмка

- У каждой найденной страницы есть результат: адрес Drupal, несколько связанных записей, черновик с причиной, подтверждённый дубль или явный пропуск.
- У каждого найденного файла есть контрольная сумма либо причина отсутствия.
- Повторный запуск не создаёт второй записи с тем же `field_source_id` и не меняет уже сохранённый материал.
- Десять источников пилота проходят `tests/archive_fetch.py`, `scripts/archive/verify_sources.py` и `tests/archive_import.php`.
- Сверка идёт по реестру снимка и по записям Drupal, а не по коду возврата команды.

## Команды

Нужен Python с `beautifulsoup4==4.14.3` и `html5lib==1.1`. Стенд должен быть уже запущен (`./scripts/local`, http://localhost:8093).

```sh
python3 -m venv /tmp/ma-archive-venv
/tmp/ma-archive-venv/bin/pip install beautifulsoup4==4.14.3 html5lib==1.1
/tmp/ma-archive-venv/bin/python scripts/archive/ma_archive.py inventory
/tmp/ma-archive-venv/bin/python scripts/archive/ma_archive.py fetch
/tmp/ma-archive-venv/bin/python scripts/archive/ma_archive.py preview
/tmp/ma-archive-venv/bin/python scripts/archive/ma_archive.py import
/tmp/ma-archive-venv/bin/python scripts/archive/ma_archive.py verify --http http://localhost:8093
```

`preview` ничего не пишет в Drupal. `resume` повторяет `fetch`, `preview` и `import`: уже скачанные файлы и существующие `field_source_id` пропускаются. `--limit N` ограничивает выборку материалов. Для отдельной копии стенда добавьте `--compose-project ma-archive-qa`. Перед первым импортом на основной стенд сделана копия базы и файлов: `~/.local/share/cigar-moscow/archive/backups/main-20261124-before-archive.sql.gz` и `main-20261124-before-archive-files.tar.gz`.

Промежуточные данные: `registry.json`, `articles/*.json`, `assets.json`, `attachments.json`, `extraction-report.json`, `inventory.json`, `plan/records.json`, `plan/questions.json`, `plan/outcomes.json`. Идентификатор материала — `item_id`. Идентификатор записи Drupal — `field_source_id` вида `legacy:journal:{id}`, `legacy:event:{id}`, `legacy:album:{id}`, `legacy:tasting:{id}:{rank}`, `legacy:cigar:{slug}`, `legacy:festival:category-{id}`. Пилотные идентификаторы и адреса копируются из `scripts/archive/pilot.json` без изменений. Зависимости создаются в порядке «выпуск, сигара, событие, альбом, журнал, дегустация». Повторный запуск ищет запись по `field_source_id` и не перезаписывает её. Каждая новая запись сохраняется отдельной транзакцией: сбой откатывает только её, следующий запуск создаёт недостающее.

Импорт остаётся Drush-скриптом пилота. Drupal Migrate не подключён: разовый перенос уже проверяет `$node->validate()`, частные файлы, повторный запуск и редакционные черновики. Отдельный веб-интерфейс не нужен.

Телефоны, почта и номера карт заменяются в видимом тексте на «[данные удалены]». Адреса фотографий не меняются. Имена организаторов остаются. Такие фрагменты не попадают в журнал импорта. Материалы с ценой, пакетом участия или призывом к покупке остаются черновиками без публичного 301. Перенаправление назначается только опубликованной записи с проверенным соответствием старого адреса.

## Вопросы клубу

Полный список лежит в `~/.local/share/cigar-moscow/archive/plan/questions.json`, 219 пунктов.

- 67 черновиков: в тексте есть цена или пакет участия. Часть дегустаций упоминает цену в магазине. Нужно решить, оставлять ли такое черновиком.
- 49 материалов: из текста убран телефон, почта или номер карты. Нужно проверить соседние фразы. Удалённое значение в вопрос не копируется.
- 40 строк рейтинга: название витолы не совпало с заголовком страницы, карточка не создана. Пример: «Juan Lopez Malecon Ехсlusivo АNDORRA» и материал 920 «Кубинские сессии 12. ВЕСЕННИЙ ПРАЗДНИК!».
- 25 выпусков: даты взяты из дат публикации материалов, а не из программы. Пример: XIV Festival del Habano 2012, 2011-11-10 — 2012-03-16. Рубрика 21 («алкогольных шедевров семьи Родионовых») выпуском не стала.
- 24 дегустации: дата взята из даты публикации. Пример: материал 426, 2011-10-25.
- 11 оценок: в обеих колонках одна и та же запись. Числа не заполнены, пока клуб не скажет, какая колонка коллективная, а какая индивидуальная.
- Строка рейтинга 92, Romeo y Julieta Cazadores, ведёт на обзор Wide Churchills. Карточка не создана.
- Страна «Армения» не сопоставлена со словарём. Куда её записать?
- У материала 336 нет заголовка. Поставлено служебное название «Материал 336».
- Формат `basic_html` при показе убирает таблицы. В базе разметка сохранена. Нужно ли отдельное исключение для архивных таблиц?

## Что восстановит резервная копия старого сайта

Публичные страницы не содержат оригиналы 713 файлов с ответом 404, шесть пустых ответов и файлы, на которые нет ссылки с открытой страницы. Копия `content/` может вернуть эти оригиналы по тем же адресам: импорт уже помечает пропуск в тексте и не назначает им контрольную сумму.

Полный состав рубрик тоже виден только из базы: сейчас метка есть у 149 материалов из 967. Оттуда же можно подтвердить даты программ выпусков и даты дегустаций, которые сейчас взяты из публикации.

Неопубликованные и служебные материалы старой CMS в этот перенос не входили. Платёжные и персональные записи из такой копии в публичный импорт и в журналы по-прежнему брать не нужно.
