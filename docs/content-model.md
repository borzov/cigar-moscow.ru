# Редакционная модель

Раздел меню объединяет материалы по назначению. Один и тот же прокур показывается на странице встречи, в карточке сигары и в рейтинге. Редактор заполняет его один раз.

| Тип материала | Основные данные и связи |
|---|---|
| Страница клуба (`club_page`) | История, президиум, традиции, награды, партнёры, вступление, контакты и условия. Поддерживает самостоятельную редакцию перевода EN. Страница `/home-cover` задаёт фотографию и подпись для главной. |
| Сигара (`cigar`) | Конкретная сигара с форматом и выпуском. Марка и страна выбираются из общих словарей. Название, формат и год или регион выпуска помогают редактору различать близкие позиции. |
| Дегустация (`tasting`) | Одна сигара, дата, необязательная встреча, три части заметки, отдельные коллективная и индивидуальная оценки от 0 до 100. Отсутствующее значение сохраняется пустым. |
| Событие (`event`) | Даты, тип встречи и необязательная ссылка на выпуск фестиваля. Один выпуск может объединять несколько событий; к одному событию относятся несколько прокуров, репортажей и альбомов. |
| Выпуск MA Cigar Fest (`festival`) | Год, начало и окончание, программа, дата показа крупного анонса, начало и окончание регистрации. После окончания выпуск остаётся по прежнему адресу. |
| Материал журнала (`journal`) | Одна или несколько редакционных рубрик, упомянутые сигары, событие и выпуск фестиваля. Пары с чаем и напитками отображаются также в разделе «Сигары». |
| Альбом (`album`) | Дата, обложка, упорядоченные ссылки на изображения, связанное событие или выпуск фестиваля. Один объект Media можно использовать на нескольких страницах. |

У каждой фотографии есть файл, альтернативный текст и место для подписи и источника. Дата публикации материала и дата самого события хранятся раздельно. Автор работает с черновиком, редактор переводит материал в опубликованное состояние. Публичные подборки используют опубликованные версии.

## Оценки

Действующее правило стенда выбирает для каждой сигары последний опубликованный прокур с коллективной оценкой по дате дегустации. При совпадении дат выбирается больший ID записи. Рейтинг упорядочен по оценке, в каждой строке есть ссылка на прокур. Клуб может согласовать другую методику перед загрузкой исторического рейтинга.

Разные дегустации одной сигары сохраняются отдельно. Для исходной записи вроде «95/89» предусмотрено `field_score_original`. При переносе числовые оценки заполняются после выяснения смысла значений. Для неясной даты или оценки исходный материал стоит оставить на редакционную разборку.

## Адреса и перенос

У материала есть `field_source_id` для идентификации записи старой системы и `field_legacy_url` для её адреса. Будущий импорт должен использовать идентификатор вместе с типом источника; запросные параметры старых страниц входят в исходный URL. Ссылки между записями создаются по таблице соответствий старых и новых ID. Марки, страны и рубрики сопоставляются с терминами словаря до создания ссылок. Рубрики допускают переименование с сохранением адреса.

Для импорта включите валидацию назначения Drupal Migrate (`validate: true`) или вызывайте `$node->validate()` перед сохранением. Так импортер выявит альбомы без связей и неверные интервалы дат по тем же правилам, что и редакторская форма.

Основной сайт остаётся на `www.cigar-moscow.ru`. Переключение проходит в три этапа.

1. Разместить прежний сайт на `archive.cigar-moscow.ru` в отдельной учётной записи, закрыть запись со стороны нового приложения и проверить изображения и внутренние ссылки архива.
2. Перенести согласованные материалы в Drupal, сверить количество и выборки по рубрикам, сохранить авторство, даты, оригиналы фотографий и подписи. При чтении старого HTML учитывать Windows-1251.
3. Настроить на основном домене адресные 301-переходы для материалов, у которых есть новый постоянный URL. Проверить входящие ссылки с параметрами, канонические адреса и Sitemap в Яндекс Вебмастере. Для архивного поддомена отдельно определить политику индексации дублей.

Параметры подключения к старому сайту и правила DNS для локальной работы не требуются.
